CrownJewel HMO

CrownJewel HMO: ERP System

Designed and built a full enterprise resource planning system for a Nigerian HMO. Covers claims processing with fraud detection, HR and attendance, financial transactions, provider registration and risk profiling, and underwriting, all behind a role-based access system with full audit trails.

01

Why I Built This

CrownJewel HMO was running core operations across spreadsheets, WhatsApp groups, and disconnected point tools. Claims were approved manually, HR attendance was tracked in Excel, and there was no audit trail for financial transactions. As they scaled to more enrollees and providers, the fragmentation was creating compliance risk and operational delays. They needed one system their entire team could work from — with different roles seeing only what they needed to see.

02

Architecture

A monolithic Next.js application with a clear separation between the public-facing pages and the protected operations dashboard. All data lives in a single PostgreSQL database managed via Prisma ORM. NextAuth handles authentication with role-based session tokens — roles are checked server-side on every protected route using Next.js middleware. The system is divided into six modules: Claims (intake, review, approval, fraud scoring), HR & Attendance (biometric import, leave management, payroll export), Finance (transactions, ledger, reconciliation), Provider Registry (credentialing, risk profiling, payment schedules), Underwriting (policy configuration, premium calculation), and Audit (immutable event log for every state change across all modules).

03

Key Decisions

  • 01

    Monolith over microservices — a small operations team doesn't benefit from distributed complexity; a single well-structured codebase is faster to build, easier to debug, and simpler to deploy.

  • 02

    Prisma's query engine gave us type-safe database access and easy schema migrations, which was critical when requirements changed mid-build (as they always do with enterprise clients).

  • 03

    Fraud detection on claims is a rule-based scoring system rather than ML — the dataset was too small for a reliable model, and rule-based scoring is explainable to auditors and adjusters.

  • 04

    Audit trail is append-only: records are never updated or deleted, only superseded — this was a hard requirement from the compliance side of the business.

04

What I Learned

  • Enterprise scope creep is real — starting with a tight feature list per module and requiring sign-off before expanding saved the project from becoming unboundedly large.

  • Role-based access needs to be designed at the data layer, not just the UI layer — UI gates can be bypassed; Prisma middleware that injects ownership filters on every query cannot.

  • Prisma's schema migration workflow (prisma migrate dev) is excellent for development but needs a clear deploy strategy in production to avoid accidental data loss during schema changes.

05

Impact

Unified 6 operational departments into one system. Reduced claims processing time from days to hours. Full audit trail now covers 100% of financial transactions.
